## Tooling and remaining work

All requested setting types are supported in the new schema. The generation command alone loses fields, and the SDK factory drops null children; the authored code restores source/build/deploy blocks after constructing each service. Local checks prove those nulls, service ownership and `preserve()` values survive SDK evaluation.

Pinned generation CLI: **5.63.4**, used only with `config migrate --show`. Light generation identified `api`; Workers generation identified `analytics-refresh-chain` and a loader inferred from a nested file. Its incomplete discovery/output was manually reconciled to the 51 actual owned services, rather than creating the inferred nonexistent loader service. Existing global CLI **5.45.0** was left unchanged.

`config plan` was deliberately not run: the current CLI can send a mutation-shaped preview operation, outside the query-only task. `config migrate status/cutover` misses null config-file paths even when deployments used an implicit root TOML. No legacy file is removed in these preparation PRs, including the loader's byte-hashed evidence file.

Use the [cutover runbook](../docs/runbooks/railway-iac-cutover.md) in Light for materialization, per-service clearing, source cleanup, idle gates, plan/apply, verification and rollback. The worker `semantic-indexer` has a custom legacy path absent from the current Workers tree and no deployment; its stored settings are included, and its actual source/runtime must be resolved before activation. Existing failed/crashed/no-deployment services are preserved as findings, not repaired or run by this migration.
